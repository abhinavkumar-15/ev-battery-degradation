# Data

Raw datasets are **never committed** (see `.gitignore`). Download them yourself, place them as shown, then run the pipeline.
Always check the licence/terms on the original dataset page before redistributing anything.

## 1. NASA Li-ion Battery Aging Dataset (primary)

* Page: <https://data.nasa.gov/dataset/li-ion-battery-aging-datasets>
* Provider: NASA Ames Prognostics Center of Excellence (PCoE). Please cite: *B. Saha and K. Goebel (2007). "Battery Data Set", NASA Prognostics Data Repository, NASA Ames Research Center, Moffett Field, CA.*

**Steps**

1. Download the archive from the page above (it contains one `.mat` file per cell, e.g. `B0005.mat`, `B0006.mat`, `B0007.mat`, `B0018.mat`, …).
2. Unzip so the files sit anywhere under `data/raw/nasa/`, e.g. `data/raw/nasa/B0005.mat`.
3. Train: `python -m src.pipeline --dataset nasa`

By default the adapter uses the four cells most often used in the literature (`B0005, B0006, B0007, B0018`; room-temperature cycling to ~30 % capacity fade).
To use others, pass `batteries=None` (all `B*.mat`) or a tuple to `NasaAdapter` in `src/data/adapters/nasa.py`.

**What the files contain** (as documented by NASA): per-step records of type `charge`, `discharge`, `impedance`.
Units: V, A, °C, s, Ah (discharge `Capacity`), Ω (`Re`, `Rct`). Cells are 18650 Li-ion, **rated 2 Ah**
(this is the reference capacity used for SOH; see `DATASET_RATED_CAPACITY_AH` in `src/config.py`).

**Project conventions**

| Item | Definition |
|---|---|
| Cycle | n-th *discharge* step of a cell (1-based); the preceding charge step is paired to it |
| Capacity | NASA's coulomb-counted discharge `Capacity` (Ah); falls back to our own ∫\|I\|dt (flagged `coulomb_count`) if absent |
| SOH | capacity ÷ 2.0 Ah × 100 |
| End of life | SOH ≤ 80 % (configurable: `--eol`). NASA's own aging tests stop at ≈ 30 % fade (1.4 Ah), so cells reach 80 % |
| Impedance | latest Re/Rct measured *before* the discharge, forward-filled (past information only) |

**Limitations:** few cells; one chemistry/format; lab conditions with constant-current discharge; small and heterogeneous sample ⇒ wide uncertainty on unseen cells.

> ⚠️ The NASA adapter was written against the documented `.mat` layout and unit-tested on a structurally identical *synthetic* file.
> It could not be run against the real download in the environment where this repository was authored.
> If your files differ slightly, adjust `parse_nasa_cell()` only — nothing downstream changes.

## 2. TBSI Sunwoda Battery Dataset (secondary — adapter slot ready)

* <https://zenodo.org/records/10715209>

Not yet integrated. To add it: convert its processed cycle summaries to one row per cycle and use
`GenericCycleCSVAdapter` (`src/data/adapters/generic_csv.py`) with a column map, register it in `ADAPTERS`, add its rated capacity to `DATASET_RATED_CAPACITY_AH`.
Cross-dataset validation (train NASA → test Sunwoda) is *not* implemented; chemistries/formats differ, so check compatibility first.

## 3. Demo / sample data (synthetic)

`data/sample/demo_cycles.csv` (≈ 560 kB, **16 simulated cells, 2,440 cycle records**; D14 never reaches end of life) is generated by `python -m src.data.adapters.demo`.
It is **synthetic**, labelled `demo` everywhere (API, UI banner, figures) and trained into a separate `models/demo/` artifact set.
It exists only so the app runs without the NASA download. Never quote its metrics as experimental results.
